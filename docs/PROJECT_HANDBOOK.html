The separation that matters

src/ holds reusable, tested library code. The run_* and analyse_* scripts are thin experiment drivers — they compose src/ and own no logic worth testing in isolation. research_pipeline.py is the Colab-style narrative version. Nothing important lives only in the pipeline file.

Name collision

ordinal_coral_loss.py is CORAL ordinal regression (Cao et al. 2020) — K−1 rank-consistent binary threshold tasks. deep_coral_alignment.py is Deep CORAL (Sun & Saenko 2016) — second-order feature covariance matching. Unrelated methods that share a name. Both files carry a cross-referencing warning header. See B6.

Any metric, CI, figure, or subgroup analysis can be recomputed without touching a GPU. regenerate_figures.py and both analysers work entirely from these.

B1What this project actually found

Four results, in descending order of how well they are established.

01

Calibration degrades where accuracy does not

On held-out DDR, QWK falls only 0.019 against source validation while ECE doubles. Every one of the four targets loses calibration. This is the thesis and the best-supported claim.

ECE 0.077 → 0.138 · ΔQWK −0.019 · n = 12,424
02

Temperature scaling transfers, then fails

Fitted only on source validation, it pulls target ECE below the source value on DDR and APTOS, leaves IDRiD 42% above, and fails on EyePACS. A practitioner cannot tell which regime they are in without target labels.

DDR 0.055 vs 0.077 · APTOS 0.041 vs 0.046 · IDRiD 0.105 vs 0.074 · EyePACS 0.180 vs 0.082
03

Cross-domain deployment costs 0.147–0.302 QWK

Measured against in-domain models on identical test images. APTOS and IDRiD are not resolvable at their test-set sizes of 354 and 102 images.

DDR −0.147 [−0.176, −0.116] · EyePACS −0.302 [−0.330, −0.275]
04

No DG method beat ERM

Across 3 seeds on DDR+APTOS → IDRiD, all five alternatives are worse on target QWK, clearing both the seed-SD and paired-bootstrap bars. The ordinal head does improve ECE by ~10× the seed noise — at the cost of collapsing grades 1 and 3.

ERM 0.7235 ± 0.0320 · best alternative 0.6778 ± 0.0068

B2Paper structure

Framing

Lead with the negative-plus-diagnostic result, not a proposed method. The contribution is a rigorous measurement and a falsification; framing it as "we propose X" invites reviewers to ask why X does not win.

Contributions to state in the introduction

  • A leakage-audited four-dataset benchmark with a documented protocol.
  • Measurement of accuracy and calibration degradation across all four leave-one-domain-out configurations.
  • Evidence that source-fitted recalibration transfers only under mild shift.
  • A negative result: four established DG methods do not beat ERM, verified across seeds with a two-bar significance criterion.

The data section is a strength — write it at length

The audit findings are unusual and reviewers will value them. Source: docs/DATA_PROVENANCE.md.

FindingNumberConsequence
One vendor folder contained 100% of APTOS3,662 / 3,662A LODO run holding out APTOS would have trained on its entire test set.
Corrupted EyePACS labels50,070 excludedGrade-3 count was 1 observed vs ~1,247 expected. 35,108 verified at 100.0000% agreement.
Vendor splits leak patients6,748 / 6,679 / 817Provided splits discarded entirely; patient-level splits rebuilt.
Byte-identical duplicates265 of 51,808224 groups, 33 with contradictory grades. Conflicting groups dropped whole, not resolved by majority.

Final corpus: 51,543 images, 17,561 patients, 4 domains — DDR 12,424, APTOS 3,504, IDRiD 507, EyePACS 35,108. State the domain numbering once and use it throughout: 0 = DDR, 1 = APTOS, 2 = IDRiD, 3 = EyePACS.

Write the protocol section defensively — it is your credibility

  • Target isolation. The held-out domain is used for final evaluation only — never training, validation, early stopping, model selection, temperature fitting, hyperparameter search, or augmentation selection. Enforced in code at splits.py::_assert_target_isolation, evaluate.py::evaluate_experiment, and checkpointing.py.
  • Patient-level splits, both eyes in the same split.
  • Temperature fitted on source validation only.
  • Two-bar significance. An effect is real only if it exceeds the across-seed SD and its paired bootstrap CI excludes zero. Justify this: the bootstrap resamples images, the SD resamples initialisations, and this project has a documented case that cleared one and failed the other.

Discussion — the clinical framing

Severe-error rate (|error| ≥ 2 grades) is the number that matters clinically, and it ranges 0.062–0.245 across targets. Temperature scaling is monotonic — it changes no prediction — so good calibration and clinical safety are separate axes. Say this explicitly; many calibration papers elide it.

B4Claims you can make

Quadratic weighted kappa falls by only 0.019 on held-out DDR while expected calibration error doubles (0.077 → 0.138), showing that discrimination and calibration do not degrade together under domain shift.
A temperature fitted exclusively on source-domain validation data reduces target ECE below the source-domain value on two of four held-out datasets, but leaves 42% and 120% excess miscalibration on the remaining two.
Relative to models trained on the target domain and evaluated on identical images, cross-domain deployment costs 0.147 QWK on DDR (95% CI [0.116, 0.176]) and 0.302 on EyePACS (95% CI [0.275, 0.330]).
Across three seeds, no domain-generalization method examined improved on empirical risk minimisation for target-domain QWK.

B5Claims you must not make

Never
A mean LODO gap.The four targets span −0.483 to +0.063. The mean (−0.122) describes none of them.
Never
That APTOS transfers better than in-domain.QWK rose (+0.063) but macro-F1 fell (−0.089). APTOS's label distribution is wider and QWK normalises by expected disagreement — a prior-shift artifact.
Never
That cross-domain beats in-domain on IDRiD.On matched images: +0.078, CI [−0.091, +0.260]. Spans zero. 102 test images.
Never
That EyePACS's collapse is domain shift.Confounded three ways: shift, the smallest training pool (11,841), and label noise. The in-domain model plateaus at 0.709 with 24,574 of its own images — ~40% of the apparent damage is the domain's own label ceiling.
Never
That Deep CORAL worsens calibration.Single-seed claim (+0.071); across 3 seeds it is +0.029 against pooled SD 0.033. Withdrawn.
Never
Any effect below 0.032 QWK at one seed.That is ERM's measured across-seed SD.
Never
Novelty for the components.Ordinal CORAL, Deep CORAL, MixStyle and temperature scaling are all prior work. The contribution is the protocol, the measurement, and the falsification.

B6The CORAL naming trap

The paper uses two unrelated methods called CORAL. Reviewers will be confused if you are not explicit. Introduce each with its full name and citation on first use, then use distinct short names throughout — "ordinal CORAL (Cao et al., 2020)" and "Deep CORAL (Sun & Saenko, 2016)" — and never the bare word "CORAL" after that. Add a footnote at first co-occurrence noting the collision is coincidental.

B7What reviewers will ask for that you do not have

GapCostPriorityWhy
A second backbone (ConvNeXt-Tiny)~2 hHigh"Is this a DenseNet artifact?" is the first question.
Single-source external~1.5 hHighThe only way to separate training-set size from domain shift for EyePACS.
Seeds on in-domain runs~1 hMediumDeployment-cost deltas carry the in-domain model's unmeasured variance.
Multiple-comparison correctionfreeMediumpaired_bootstrap_difference returns "uncorrected for multiple comparisons". Apply Holm–Bonferroni before calling anything significant.
DINOv2 / foundation-model baseline~2 hMediumReviewers increasingly expect one.
Hyperparameter sensitivityhighLowBut state plainly that no search was performed, on any domain.

The first two are cheap and would materially strengthen the paper — about 3.5 hours of compute closes both obvious review gaps.

B8Reproducibility package

Everything needed is present: code and 227 tests; configs with unknown-key rejection so a config cannot silently disagree with the run it describes; the registry with one row per run; per-image predictions making every claim recomputable without a GPU; and the ledger.

Refresh README.md, add a LICENSE, add a data-access statement — the four datasets are public but each has its own terms (DDR; APTOS 2019 via Kaggle; IDRiD via IEEE DataPort; EyePACS via Kaggle) — and state that raw images are not redistributed. B10Writing conventions specific to this project

Always
One sign convention.Use Δ = target − source (or LODO − in-domain) everywhere, so negative always means worse. Two bugs in this codebase came from mixing conventions between a table and the sentence describing it.
Always
Print n with every CI.Test sets range from 102 to 35,108 images. An interval without its n is uninterpretable.
Always
Report QWK and macro-F1 together.They disagree under prior shift, and the disagreement is a finding, not an inconsistency to hide.
Never
Average over a partial matrix.analyse_lodo.py refuses to, by design.
Never
Omit a missing result silently.Say NOT RUN. An absent row and a bad row look identical once a mean is taken.
